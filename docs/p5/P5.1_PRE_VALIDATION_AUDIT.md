## 1. Current P5 Pipeline Overview

The Phase P5 computer vision pipeline is fully modularized under `src/cv/`, executing an 8-stage synchronous/asynchronous chain:
1. `ImageIngestion.normalize()`: Image buffer validation, dimension clamping (max 1024px), luminance conversion.
2. `ImageQualityAnalyzer.analyze()`: Laplacian sharpness, exposure, contrast, glare, and per-border framing checks.
3. `HandDetector.detect()`: Skin-chrominance bounding locus, hand presence, handedness classification, and 21-point anatomical landmarks.
4. `PalmSegmentation.extractPalmROI()`: Wrist-to-MCP9 orientation calculation, inverse-rotation affine warp to 512×512 patch, inner palmar falloff masking.
5. `CreaseEnhancementEngine.enhance()`: 8×8 CLAHE local contrast equalization, multi-scale Gaussian 2nd-derivative / Hessian directional valley response (scales: σ = 1.0, 2.0, 3.5).
6. `CreaseCandidateGraph.extractCandidates()`: Binarization (τ = 0.18), Zhang-Suen morphological thinning to 1-pixel centerlines, connected graph tracing, spur pruning (< 12px), Douglas-Peucker polyline simplification.
7. `MajorLineClassifier.classify()`: Anatomical prior sector matching, directional span & orientation gating, multi-signal scoring, honest `NOT_DETECTED` designation.
8. `PalmFeatureModelAdapter.toPalmFeatureModel()` & `polylineToSvgPath()`: Translates vision results into canonical `PalmFeatureModel` and SVG paths for `PalmLineOverlay`.

The baseline test corpus in [goldenCorpus.js](file:///Users/Hp/Documents/Kai%20RegAI%20%28clone%29/src/cv/dataset/goldenCorpus.js) defines 12 deterministic synthetic test cases:

* Framing & presence: `clipped_palm`, `no_hand`
* Crease presence variations: `faint_sun_line`, `absent_sun_line`

**Audit Finding:** The synthetic corpus successfully validates mathematical algorithm invariants (e.g. that a flat image triggers blur rejection, or an unannotated Sun line produces `NOT_DETECTED`). However, synthetic creases do not exhibit the micro-textural irregularity, specular highlights, varied skin folds, and lighting gradients of real human hands.

## 3. Current Evaluation Metrics

Implemented in [Evaluator.js](file:///Users/Hp/Documents/Kai%20RegAI%20%28clone%29/src/cv/dataset/Evaluator.js):
* **Geometry:** Mean point-to-curve Euclidean distance, endpoint localization offset.
* **Segmentation:** Intersection over Union (IoU), Dice coefficient.
* **Continuity:** Chord length / arc length ratio.
* **Quality Gate Accuracy:** Agreement between predicted gate pass/fail vs expected status.

**Audit Finding:** The evaluator lacks symmetric Hausdorff distance, median distance (for outlier resilience), and normalized error relative to palm reference dimension (e.g. normalized to palm width/span).

## 4. Current Line-Classification Strategy

Implemented in [MajorLineClassifier.js](file:///Users/Hp/Documents/Kai%20RegAI%20%28clone%29/src/cv/crease/MajorLineClassifier.js):
* Matches candidate paths against anatomical bounding sectors (`startZone`, `endZone`).
* Directional trajectory gating:
  * Vertical lines (Fate, Sun): requires $|dy| \ge 0.18$ and $|dy| \ge |dx| \times 0.85$.
  * Transverse lines (Head, Heart): requires $|dx| \ge 0.18$ and $|dx| \ge |dy| \times 0.70$.
* Scoring formula:
  $$\text{Score} = 0.40 \cdot \text{Prior} + 0.30 \cdot \text{Structure} + 0.15 \cdot \text{Contrast} + 0.15 \cdot \text{Continuity}$$
* Thresholds: $\tau_{\text{detection}} = 0.55$, $\tau_{\text{weak}} = 0.35$. Below $\tau_{\text{weak}} \to$ `NOT_DETECTED`.

## 5. Current Coordinate Systems

The system uses three distinct coordinate systems:
1. **Original Image Coordinates $(X_{\text{orig}}, Y_{\text{orig}})$:** $[0, W_{\text{orig}}] \times [0, H_{\text{orig}}]$
2. **Rectified Palmar ROI Coordinates $(X_{\text{patch}}, Y_{\text{patch}})$:** $[0, 512] \times [0, 512]$, rotated such that the wrist-to-middle-MCP vector is vertical ($0^\circ$).
3. **Normalized Patch Coordinates $(x, y)$:** $[0, 1] \times [0, 1]$ relative to the $512\times 512$ patch.
4. **SVG Overlay Coordinates $(x_{\text{overlay}}, y_{\text{overlay}})$:** $[0, 360] \times [0, 450]$ mapped into `PalmLineOverlay.js`.

**Audit Finding:** Polylines in `PalmVisionResult.lines.*.polyline` are currently stored in Normalized Patch Coordinates. An explicit, bidirectional mathematical transformation matrix between $(X_{\text{orig}}, Y_{\text{orig}})$ and $(x_{\text{overlay}}, y_{\text{overlay}})$ must be formalized to guarantee overlay alignment with source photographs.

## 6. Current Image Normalization

In [ImageIngestion.js](file:///Users/Hp/Documents/Kai%20RegAI%20%28clone%29/src/cv/image/ImageIngestion.js):
* Bilinear downsampling clamps images whose max dimension exceeds 1024px.
* Converts 4-channel RGBA to 8-bit grayscale using integer coefficients:
  $$Y = (77R + 150G + 29B) \gg 8$$
* Aspect ratio is preserved.

## 7. Current Palm ROI Logic

In [PalmSegmentation.js](file:///Users/Hp/Documents/Kai%20RegAI%20%28clone%29/src/cv/detection/PalmSegmentation.js):
* Palm center: midpoint between Wrist (Landmark 0) and Middle MCP (Landmark 9).
* Orientation: $\theta = \text{atan2}(dx, dy)$ between Wrist and Middle MCP.
* Radius: $0.75 \times \max(\text{palmSpan}, \text{palmHeight})$.
* Inner mask: $\text{normDistSq} \le 0.65$ to eliminate outer skin-to-background edge artifacts.

## 8. Current Crease Enhancement Logic

In [CreaseEnhancementEngine.js](file:///Users/Hp/Documents/Kai%20RegAI%20%28clone%29/src/cv/crease/CreaseEnhancementEngine.js):
* $8\times 8$ tile CLAHE with clip limit $2.5$.
* Gaussian smoothing + centered discrete 2nd derivatives ($I_{xx}, I_{yy}, I_{xy}$).
* Maximum positive eigenvalue:
  $$\lambda_2 = \frac{I_{xx} + I_{yy} + \sqrt{(I_{xx} - I_{yy})^2 + 4I_{xy}^2}}{2} \cdot \sigma^2$$
* Scales: Fine ($\sigma=1.0$, weight $0.25$), Medium ($\sigma=2.0$, weight $0.50$), Coarse ($\sigma=3.5$, weight $0.25$).

## 9. Current Graph & Skeletonization Logic

## 11. Known Algorithmic Limitations on Real Images

1. **Uneven Lighting & Skin Luma Gradients:** CLAHE mitigates global exposure differences, but strong directional sidelight creates shadow ridges along hand folds that can compete with true creases.
2. **Skin Texture vs Micro-Creases:** Natural skin creases in dry palms have varying furrow depths.
3. **Anatomical Prior Boundary Rigidity:** If a user's hand is held with unusual finger spacing or high perspective distortion, rigid sector bounds may slightly penalize genuine creases.
4. **Coordinate Inversion Risk:** If the transformation chain between rectified patch and original photograph is not bidirectionally verified, overlays will appear systematically displaced.

## 12. Insertion Points for Real-Palm Validation

Validation integrates cleanly without altering P5 core logic:
1. **Validation Ingestion:** Read real palm images (JPEG/PNG) from `cv/real-validation/raw/` into standard `PalmImage` format.
2. **Ground-Truth Annotations:** Compare real predictions against canonical JSON annotations (`PalmAnnotation`) in `cv/real-validation/annotations/`.
3. **Evaluation Runner:** A dedicated test suite `tests/cv/p5_1_real_validation.test.js` computing symmetric Hausdorff distance, median distance, endpoint error, and failure taxonomy tagging.
4. **Calibration Harness:** A threshold sweep runner (`cv/real-validation/ThresholdSweeper.js`) measuring sensitivity of key parameters against real images.
5. **Developer Visualizer:** An interactive HTML/SVG validation viewer (`cv/real-validation/viewer/`) rendering Ground Truth (Green), Detected Creases (Cyan/Magenta), and Error vectors.
