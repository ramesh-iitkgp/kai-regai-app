# P9 Pre-Implementation Audit: AI / RAG Narration Engine

## 1. Executive Summary

Phase P9 introduces the **AI / RAG Narration Engine** for Kai RegAI. Its single architectural mandate is:
> **P8 DECIDES. P9 EXPLAINS.**
> P8 (`InterpretationDossier`) is the single source of interpretation truth. P9 is strictly a narration, synthesis, tone-calibration, and natural-language presentation layer. P9 has zero authority to inspect raw pixels, invent palm features, alter rule matching, or generate deterministic future predictions or medical diagnoses.

This audit inspects the existing repository state, establishes baseline invariants, and defines the technical blueprint for P9 implementation.

---

## 2. P8 Architecture Review

Phase P8 established a deterministic, decoupled interpretation pipeline:
$$\text{PalmFeatureModel} \longrightarrow \text{FeatureNormalizer} \longrightarrow \text{RuleEngine} \longrightarrow \text{EvidenceCollector} \longrightarrow \text{ConfidenceEngine} \longrightarrow \text{ConflictResolver} \longrightarrow \text{SynthesisEngine} \longrightarrow \text{EpistemicGate} \longrightarrow \text{InterpretationDossier}$$

* **Performance**: Pipeline executes deterministically in **< 8 ms**.
* **Integrity**: 38 declarative rules statically verified via `CodexValidator`.
* **Determinism**: 100% bitwise repeatability across runs with zero LLM dependence.
* **Test Baseline**: 104 passing tests across P5.1, P5.2, P6, P7, and P8.

## 3. `InterpretationDossier` Structure

The master artifact generated by P8 (`src/interpretation/InterpretationDossier.js`) contains:
* `id`, `mode` (`MODE_1_SCANNER` | `MODE_2_QUESTIONNAIRE`), `reading_method`, `title`, `timestamp`, `hand_side`, `hand_dominance`, `summary`
* `quality_score`, `confidence`, `confidence_band` (`HIGH` | `MODERATE` | `LOW` | `INSUFFICIENT_EVIDENCE`)
* `tags`: Array of metadata descriptors
* `major_lines`: Array of 5 lines (`life_line`, `head_line`, `heart_line`, `fate_line`, `sun_line`) each containing:
  * `tier1_observation`: Physical morphology
  * `tier2_western`: Classical Western attribution & citation
  * `tier3_hasta_samudrika`: Vedic Samudrika attribution & citation
  * `tier4_synthesis`: Kai RegAI integrative summary
  * `confidence`, `status`, `color`, `symbol`
* `synthesis_chapters`: 4 core thematic narratives (`constitution`, `vocation`, `relationships`, `guidance`)
* `features`: Detailed sub-objects for `mounts`, `thumb`, and `markings`
* `evidence`: Array of verifiable `EvidenceRecord` items tracing conditions to source observations
* `multi_source_agreements`: Concordances between Western and Indian traditions
* `conflicts`: Documented divergences between traditions handled with dual-perspective synthesis
* `provenance`: Engine versioning, codex version (`1.0.0`), and safety verification flags
* `getExplanation(domain)`: Explainability query method.

## 4. Existing Report Pipeline Review

* **Quick Report (`QuickReportScreen.js`)**:
  * Consumes reading summary, confidence badge, line presentation (`DETECTED`, `PARTIAL`, `OUT_OF_FRAME`, `NOT_DETECTED`), and glowing line overlays.
  * Designed for immediate ~10s consumption. Requires concise narrative (150–250 words), 3–5 key takeaways, and zero technical jargon.
* **Detailed Report (`DetailedReportScreen.js`)**:
  * Organizes reading across 4 tabs: `OVERVIEW`, `LINES`, `FEATURES`, `SYNTHESIS`.
  * Renders full 4-chapter narrative breakdowns, source citations, mount evaluations, and interactive line filters.
  * Requires rich, empathetic, coherent prose (1,000–1,800 words) with source explainability.

  * `western/`: Cheiro, Benham, Saint-Germain citations.
  * `hastaSamudrika/`: Samudrika Shastra, Narada Samhita, Bhavishya Purana citations.

## 6. Existing Epistemic Safety Gates

P8's `EpistemicGate.js` enforces:
* Zero fatalistic claims: bans `you will die`, `inevitable accident`, `guaranteed divorce`, `fixed wealth`.
* Zero medical diagnoses: bans `cardiac condition`, `clinical depression`, `organ pathology`.
* Epistemic framing: converts absolute assertions into conditional traditional attributions (*"traditionally associated with"*).

P9 must incorporate this as a double-layer gate (`NarrationSafetyGate.js`) operating on generated text.

---

## 7. AI Dependencies, Environment Variables & Network Boundaries

* **Current Repo State**:
  * Zero runtime dependencies on external AI SDKs (`package.json` contains only `vite` and `jpeg-js`).
  * Zero hardcoded API keys or environment leaks.
* **Architectural Strategy for P9**:
  * Abstract AI provider interface (`LLMProvider.js`).
  * Built-in `DeterministicNarrator.js` ensuring 100% offline functionality and zero external network dependence for core product delivery.
  * Built-in `MockLLMProvider.js` providing deterministic, fast mock generation for automated test suites.
  * Pluggable adapter stubs (`GeminiProvider.js`, `OpenAIProvider.js`) configured to ingest keys strictly via server-side boundaries or external environment variables, never bundled into client JS.

---

## 8. Existing Prompt Logic & Report UI

* No hardcoded prompts currently exist in the UI components.
* P9 must introduce a centralized `PromptCompiler.js` that deterministically compiles structured prompts from the `InterpretationDossier`.

## 10. Key Identified Risks & Mitigation Strategies

| Risk | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **Hallucination of Palm Features** | Critical | Strict `EvidenceConsistencyChecker`: any narrative referring to a feature not in the P8 evidence record is rejected immediately. |
| **Fatalistic / Medical Claims** | Critical | Multi-stage regex and semantic firewall (`NarrationSafetyGate`) with immediate fallback to deterministic text. |
| **External LLM Latency or Downtime** | High | `DeterministicNarrator` provides complete, human-grade offline narration in < 5ms. |
| **Confidence Inflation** | High | Mathematical ceiling: narrative assertion strength cannot exceed P8 confidence band (`Narration confidence <= P8 evidence confidence`). |
| **Prompt Injection via RAG or User Input**| High | RAG is strictly restricted to local, immutable Codex data. User context is sanitized and treated as data, never as system instructions. |
